# Assets, Audio, and Realm Asset Pipeline

- `ProceduralRetroAssets` generates textures at startup with LibGDX `Pixmap`s and packs starter character/NPC sheets, item icons, paperdolls, projectiles, and animation strips into shared power-of-two GPU atlas pages via pure `TextureAtlasPacker` (with 1 px transparent gutters; realm manifests in `applyManifest` are similarly batch-packed, falling back to standalone textures for large sheets or tilesets). Accessors: `getTileRegion`, `getSpriteRegion`, `getItemIconRegion`, `getPaperdollRegion`, `getPaperdollLayerFrame`, `getOrComposeCharacterRegion`, `getProjectileRegion`, `getAnimationRegion`. Supports custom overrides via `registerCustomTileset`, `registerCustomSprite`, `registerCustomPaperdoll`, and `applyAssetEntry`.
- `ProceduralTilesetGenerator` generates 32x32 retro pixel-art map tilesets using periodic (toroidal) value noise, fractional Brownian motion (fBm), periodic Voronoi distance fields (for cobblestones and rocks), and curated color ramps. Because noise and Voronoi coordinates wrap seamlessly at 32-pixel periods, terrain tiles (grass, dirt, water caustics, sand, snow, ice, cobblestone) tile seamlessly across maps without edge artifacts. Supports starter (16x3) and expanded (16x6+) overworld sheets with terrain variants (tufts, wildflowers, clover), nature decals (stumps, mossy logs, boulders), and autotile transition edges. Lives in the engine-free [tilegen module](/architecture/tilegen.md) and draws into a `TileImage`; `ProceduralRetroAssets` converts it with `toPixmap()` for the default runtime art, and `GenerateTilesetTool` (`:client-desktop:generateTileset`) exports it.
- `RetroSoundEngine` synthesizes 16-bit PCM chiptune effects (`Sfx`: SWING, HIT, CRIT, SPELL, HEAL, LEVEL_UP, PICKUP, WARP, CLICK) and procedural background music themes (`BgmTrack`: `TOWN_THEME` (`town_theme`), `FIELD_THEME` (`field_theme`), `MARSH_THEME` (`marsh_theme`), `DUNGEON_THEME` (`dungeon_theme`)). Hands each synthesized WAV to a platform `SoundLoader`: the default `TempFileSoundLoader` (desktop, Android) writes temporary `.wav` files (`morgana_sfx_*`, `morgana_bgm_*`) and loads them as LibGDX sounds; the browser uses `BrowserSoundLoader` ([client-web](/architecture/client_web.md)), which passes the bytes to Howler. Tracks loop seamlessly via `playBgm(trackId)` when entering maps with `bgmTrackId`; switching tracks **crossfades** (about 1.2 s; `update(delta)` runs the fade each frame, `fadeOutBgm()` is used for a map with no music, `stopBgm()` stops at once). `MorganaGame` calls `loadAll()` once at login (while the world is held back) so no effect or theme is synthesized mid-frame; before that the first town visit hitched. Realm-shipped music (`assets/music/<trackId>.ogg`, manifest kind `MUSIC`) is registered after the manifest is applied (`MorganaGame.applyRealmArt`) with `registerCustomTrack` and decoded on first play through `SoundLoader.loadEncodedTrack`; `playBgm` prefers a shipped track over a built-in theme of the same id, and `clearCustomTracks()` runs at every login so a realm never inherits the previous one's music. A loader that fails leaves that effect silent without an error, so check `RetroSoundEngine.loadedCount` and `bgmLoadedCount` when audio seems missing.
- `RealmAssetSyncPipeline` manages content-addressed asset synchronization: inspects the remote realm's `AssetManifest`, calculates missing un-cached entries, streams files via `AssetDownloader` (`HttpAssetDownloader`), validates cryptographic SHA-256 checksums, and caches them atomically into `AssetCache` (`FileAssetCache`) before entering the world. The server side, a game's `assets/` folder, is described in [game-owned art](/server/game_assets.md); `assetBaseUrl` may contain `{host}`, which `MorganaGame` replaces with the host the player connected to. A realm's art never outlives the realm: every successful login (including resume) first cancels any in-flight sync and calls `resetCustomArt()`, which restores the built-in sheets through `ReplaceableArt` (remembers what each id displaced; pure and unit-tested) and disposes the realm's textures, then applies the new manifest. Until that is done `MorganaGame` holds the world and HUD back (`artLoading`, `PlayerHudAndWindows.holdBack`) so the built-in placeholder art never flashes before the realm's art replaces it; the hold ends when the art is applied, the download is cancelled, or the player returns to login. `syncAsync` has no thread of its own: it fetches files one at a time through `AssetDownloader.downloadAsync(url, onDone)`, so the same pipeline runs on the JVM (`HttpAssetDownloader` supplies a worker thread per download) and in the browser (`BrowserAssetDownloader`, `fetch`, one thread; see [client-web](/architecture/client_web.md)). Callbacks arrive inline, from another thread, or later; progress and completion run on whichever thread the downloader finished on, so `MorganaGame` hops to the render thread. `AssetDownloadDialog` displays interactive progress in VisUI. See [ADR 0014](/decisions/0014_morgana_realms_universal_client_architecture.md).
