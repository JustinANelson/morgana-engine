# F1 Live Editor (`F1LiveAdminPanel`)

Toggled with `F1` for Mapper and above ([access levels](/domain/access_levels.md)); the toolbar's **Close editor** button does the same. The editor is a set of **editors** (called *panels* in the code: `EditorPanel`, `DockLayout`) found through the toolbar's **Editors** button: Tileset, Layers, Attributes, Maps and Map properties (the map editor), Items, NPCs, Spells, Shops, Resources, Recipes, Quests, Animations and **Events** (the content editors), Art, Help, **Settings** (the colour scheme), and a small **Admin tools** window. Each is described below.

### Visual Asset Pickers (`AssetPickers.kt`)
Rather than typing blind numeric IDs, the editor provides visual modal pickers:
* **`VisualIconPickerDialog`**: 6-column interactive grid showing every available 32x32 item and spell icon with selection highlights.
* **`VisualSpritePickerDialog`**: Interactive grid showing character and NPC directional sprites rendered in idle stance, returning the selected sprite ID.
* **`VisualAnimationPickerDialog`**: Interactive list displaying animation definitions with frame counts, durations, and sound triggers.

### Events and animations
* **Events panel** (`EventsPanel` over `EventEditSession`, sharing `StepTreePane` with `CommonEventsPanel`, and `EventForms`; added 2026-11-13, replacing the Studio's hand-built Events tab): three columns. **Left**, the searchable list of events and **New event**. **Middle**, the event's name and map tile (**Use where I am standing** fills it in, **Place or move on map** switches to the Event map tool, **Copy to another map...** duplicates the event onto a chosen map and coordinates with `EventEditSession.duplicateToMap`; a line says what starts the event: its tile and every creature whose Event points at it), the **pages** (add, copy, delete, move earlier or later; a line says in words when the page is used, and that the last fitting page wins) and the page's settings: what starts it, what it looks like, and every condition the server checks (switch on or off for **This player** or **Whole world**, a player or world number at least so much, a quest in progress or completed, an item carried, a level). **Right**, the page's **steps** in plain words with the names of what they point at ("Give 2 x Iron Key (#3)"), a dialogue's **answers** and their own steps indented under it, buttons to move, copy and delete the selected step or answer, **Add answer**, and a pick-list of every kind of step grouped by purpose (Talk, Items, Player, Memory, Quests, Windows, Effects, Flow, Advanced) with a one-line explanation; below, the **selected step's own fields** (item and shop ids show the name they point at, animations have a picker, switch/number steps choose **This player** or **Whole world** scope). A new step goes after the selected step, under the selected answer, or at the end. Everything wrong is listed with its page and step ("Page 2, step 3: item 8 does not exist") and blocks Save; **Undo** and **Redo** cover every change, and typing in one form is one undo step. Nothing reaches the server until **Save event**. The old tab could add 8 of the 15 kinds, could not edit a step after adding it, had no answers, saved the event whenever a page was added, and offered two of the five conditions. The editor also flags a quest condition with no state chosen, because the server does not check one. Tests: `EventEditSessionTest`, `EventFormsTest`, the shipped events in `ShippedContentFormsTest` (every shipped event passes through the editor unchanged, and a new event with every kind of step passes the server's rules), and a browser smoke step. **If steps and the other new kinds (2026-11-13)**: the pick-list has a **Flow** group with *If ... otherwise*, *Run common event*, *Wait*, *Set a label*, *Jump to label*, *Repeat loop*, *Break loop*, and *Stop the event*, plus *Set a number*, *Show a chat message*, *Ask for input*, *Teach a spell*, *Play a sound*, *Show a picture*, and *Move a creature* (30 kinds in all). Speech, chat messages and input prompts accept `{...}` placeholders (`{player}`, `{level}`, `{visits}`, `{item:1}`). An If step reads in words ("If the player carries 2 x Iron Key (#3):") with **Then:** and **Otherwise:** lines under it (and *Repeat loop* shows **Do each pass:**); select one and Add step puts the step inside it. Its form asks what to check (a player/world switch, a player/world number, an item carried, a quest's state, level, class, a known spell, or a random chance) and then shows only the fields that check uses; **Add condition** / **Remove last condition** let one If step combine several checks under **All of these match** or **Any one matches**. Then, Otherwise, and Do each pass cannot be moved or deleted; the enclosing step itself can, with everything under it. How these run is on the [events page](/systems/events_quests.md). `FormFieldsView` is the field-drawing code shared with `ContentEditorPanel` (it was private to it), and list rows that are too long now end in "..." instead of spilling out of both sides (`listButton`). **Map placement (2026-11-13)**: the **Event** tool (**V**) draws a marker (`E#<id>`) on the map for every event on it (highlighting the one open in `EventsPanel` at its live draft position); left-clicking a marker selects that event in the Events panel, left-clicking an empty tile moves the open event there (or places a new event when none is open), right-clicking an empty tile starts a new event there, and right-clicking a marker unplaces it (`mapId = 0`). **Test from here (2026-11-13)**: the **Test from here** button runs the current page starting from the selected step (or branch) through the rest of the page on the editing admin's own character (`c_admin_test_event`) without saving the draft or altering the saved catalog; dialogues open over the editor and resume even for unsaved events.
* **Common events panel** (`CommonEventsPanel` over `CommonEventEditSession`, sharing `StepTreePane` with `EventsPanel`): edits reusable or automatically triggered step sequences saved to `common_events/` (`c_admin_save_common_event`), sets `CommonEventTrigger` (`MANUAL`, `ON_TIMER` with `intervalTicks`, `ON_LOGIN`, `ON_LEVEL_UP`), shows automatic triggers and callers (`commonEventUsedBy`), and supports **Test from here**, Undo/Redo, and validation.
* **Animations panel** (`AnimationForm` over `ContentEditorPanel`): sprite sheet, number of frames, time per frame (`frameDurationMs`), linked sound and whether it draws over characters (`renderAboveEntities`). It used to be a Studio tab; it is now an ordinary content panel like Items.

### Complete Schema Coverage
All schema fields are exposed in the GUI tabs:
* **Spells**: `iconId` (visual picker), `animationId` (visual picker), `castTimeTicks`, `spCost`, `aoeRadiusTiles`, and `projectileSpriteId`.
* **NPCs**: `spriteId` (visual picker), multi-drop loot tables (item, min/max quantity, basis-point chance), overhead title, and comma-separated spell lists.
* **Shops**: `currencyItemId`, buy/sell rate percentages, and stock inventory.
* **Resources**: `respawnTicks`, `xpReward`, `intactSpriteId`, and `depletedSpriteId`.

**Map editing model** (`MapEditSession`, in `client/editor/`): all map-editing rules live in one pure, unit-tested class with no graphics or networking, so any window layout just drives it. It owns the *draft* (a private working copy of the map; every change also shows live as the active map), the tool (`MapEditorTool`: Paint Brush, Eraser, Flood Fill, Rectangle Fill, Eyedropper, NPC Spawn, Event), the current layer, a **stamp brush** (a rectangle of up to 16 x 16 tiles cut from one tileset, clipped at map edges), the attribute to paint (with or without graphics), per-layer visibility, and **undo/redo**. An undo step is a *stroke*: the game calls `beginStroke` on mouse-down and `endStroke` on mouse-up, so a whole drag is one step; lone edits are their own step; no-op edits record nothing; history keeps the last 100 steps. `isDirty` compares the draft with the last loaded or saved version. Painting never bumps the revision, only an explicit save does. `ClientWorldState` exposes the same state through its old properties (`selectedTool`, `selectedSrcTileX`, `workingMapDraft`, ...) as thin views of `ClientWorldState.editor`, and Save still sends `c_admin_save_map`. Tests: `MapEditSessionTest`.

**Editor look** (`client/ui/editor/`): the theme every editor panel is built from. `EditorPalette` is one **colour scheme** as pure values; `EditorPalette.SCHEMES` lists six (owner feedback 2026-11-13 asked for a look that does not read as every AI-assisted tool's dark grey and blue): **Ember** (warm charcoal, amber accent; `DEFAULT`), **Parchment** (light: cream, dark ink, teal), **Moss and brass**, **Royal plum**, **Slate** (the original grey and blue) and **High contrast**. Every scheme's readability is unit-tested against WCAG contrast thresholds (7:1 for text, including `strong` text on the selected fill; 4.5:1 for muted text and accents; quiet but visible borders). The **Settings** editor (`SettingsPanel`, group Tools) lists the schemes with colour swatches; **Use** saves the choice through `EditorSettings` (platform preferences `morgana-editor-settings`, key `color-scheme`; an unknown id falls back to the default) and rebuilds every editor with a new `EditorTheme(palette)`, keeping the map draft and reopening Settings (`F1LiveAdminPanel.applyColorScheme`). `GameTheme.shared` (HUD, inventory, shop, realm hub, wizard, character select) is one long-lived theme whose styles and `dynamic` drawables are re-pointed in place on a scheme change (`GameTheme.retint`), so open windows recolour live; those windows take their muted/good/bad/warning/gold colours from the palette (`success`, `danger`, `warning`, `accent`, `textMuted`) and use `cardBackground` / `selectedCardBackground` instead of raw VisUI skin drawables. `SkinThemer` (`client/ui/`) applies the saved scheme to the shared VisUI skin at startup and on every change (it mutates the stock window, label, button, text field and checkbox styles in place), so the in-game windows (quest log, spellbook, bank, dialogue, party, settings) and `GameTheme` follow the scheme too; drop-downs and lists keep VisUI's own look. `IconArt` is the icon set, 24 hand-drawn 16 x 16 pixel icons (brush, eraser, bucket, picker, spawn, undo, redo, save, grid, zoom, eye, layers, tiles, attribute, map, close, float, dock, ...) written as text rows, so they diff and review like code and a test checks every row. `EditorTheme` (needs a graphics context and a loaded VisUI) builds the icon sheet and the editor's own styles in code (window, push button, tab with accent underline, icon toggle button, labels, tooltip, separator) and small factories (`window`, `textButton`, `tab`, `iconButton` with tooltip, `selectGroup`, `heading`); the game's HUD keeps the stock VisUI skin. The F1 window now uses it: themed title bar and close button, a real tab strip, icon tool buttons with tooltips, toggle layer buttons, section headings. Tests: `EditorPaletteTest`, `IconArtTest`. Verified in Chrome.

**Panel system** (`EditorWorkspace`, `DockLayout`): the editor is a set of panels, each either **docked** to a screen edge (toolbar along the top and status bar along the bottom spanning the full width, tall panel columns on the left and right, the classic Mirage arrangement) or **floating** over the world. `DockLayout` (pure, unit-tested: `DockLayoutTest`) decides everything: which zone and position each panel has, floating position and size (kept reachable on screen), hidden and collapsed state, the rectangle each panel occupies on a given screen, the drag-to-dock edge rule, and a saved text form that tolerates damaged or outdated data. `EditorWorkspace` draws it: each panel has a header with float/dock, collapse and hide buttons; drag a docked header to pull the panel out; drag a floating panel near an edge and a highlight previews where it will dock when released; floating panels have a resize grip; the arrangement is remembered through `PreferencesLayoutStore` (a file on desktop, local storage in a browser). **The world is centred in the free space**: `MorganaWorldRenderer.viewInsets` shifts the camera by half the covered area (`ViewInsets.cameraShift`), and click-to-tile mapping follows because it derives from the same camera. Panels absorb mouse presses, so painting never reaches the world through a panel. The F1 editor now opens as a toolbar (save, undo, redo, map name, "unsaved changes" marker, buttons to bring back hidden panels and to reset the layout), a status bar (tile under the pointer, tool, layer, undo steps), the tile palette, and the existing tabbed "Editor Studio" panel (its tab strip scrolls sideways when narrow). Verified in Chrome.

**Tile palette** (`TilesetPanel`, `TilesetSelection`): every tileset the game has (the built-in one and any a realm ships, see [game-owned art](/server/game_assets.md)) is stacked top to bottom in one scrolling pane as its real image, with a two-tone chessboard behind transparent cells, a faint grid, and **no per-tile captions**, so large standard sheets (Time Fantasy style, hundreds of tiles) fit. The palette is a fixed **8 tiles wide** (256 px at 100%, RPG Maker XP's tileset width; owner feedback 2026-11-13), and the left column is 288 px to fit it: a wider sheet is cut into 8-wide strips stacked one under another, with a brighter line where it was folded (`PaletteStrips`: `toSheet`, `toDisplay`, `selection` keeps a drag inside the strip it started in, `displayRects` draws a block that crosses a strip edge in each strip). Objects up to 8 tiles wide inside one strip stay intact, and the palette only scrolls down (sideways only when zoomed in past the column). Above the sheets, **Anim** sets the brush's animation: **-/+** for the number of frames (Still, 2, 3, ...) and for the time each frame shows (50 ms to 2 s, `ANIMATION_SPEEDS`, `stepSpeed`); painted tiles then cycle through the tiles to their right, a brush-width apart so a stamp animates as one object (`MapEditSession.animationFrames`, `animationSpeedMs`; `placementFor` sets `animationFrameStep` to the brush width; the eyedropper picks up a tile's animation). The line under the sheets says what will happen, or warns when the frames would run off the sheet. Click a tile to select it; **drag to select a block** (a stamp, up to 16 x 16) that is painted as one. A map can use tiles from several tilesets (each placement stores its tileset): pick from any section and keep painting. A "Jump to" box scrolls to a tileset, each section header collapses it, and zoom (50%, 75%, 100%, 125%, 150%, 200%) applies to all sheets. `TilesetSelection` and `PaletteStrips` hold the geometry (cell under the pointer, strips, drag block clamped to the strip and to the stamp limit, zoom steps; `TilesetSelectionTest`).

**Toolbar, layers and map aids**: (on a window narrower than the toolbar, about 1000 px, the toolbar scrolls sideways with a thin scroll bar instead of cutting buttons off) the toolbar now carries the seven tools (brush, rectangle, bucket, eraser, eyedropper, NPC spawn, event; the highlighted one follows the session, so the eyedropper's switch back to the brush shows), a grid toggle and zoom out / in (the editor's own levels, 25% to 400% in steps of a quarter or half: `WorldZoom.EDITOR_LEVELS`, `stepEditor`; keys **-** and **=**; the status bar shows the zoom; the editor zoom applies only while the editor is open, and closing it returns to the game's whole-step zoom; owner feedback 2026-11-13: one step from 1x to 2x went too far). The **Layers** panel (`LayersPanel`, docked left under the tile palette) has a **Clear** button under the list that empties the selected layer across the whole map (owner feedback 2026-11-13: "clear all Mask 1"; the first click arms it and names the tile count, the second clears; `MapEditSession.clearLayer` is one undo step that keeps other layers, attributes and spawns, `tilesOn` counts a layer's tiles; disabled when the layer is empty). It lists every `MapLayer` top first: the eye button hides or shows a layer in the editor only (`MapEditSession.hiddenLayers`, honoured by the renderer, never saved), the name button picks the layer that painting and erasing target, and a note says whether it draws above or below characters. The map shows a faint tile grid (`showGrid`) and a **ghost of the whole stamp** under the pointer (one tile for the bucket). The **rectangle tool** is now live: press marks the first corner, drag shows a green box (red with the right button, which clears), release fills it with the stamp repeated across the box as one undo step (`beginRect` / `finishRect` / `cancelRect` in `MapEditSession`).

**Attributes panel** (`AttributePanel` over the pure `AttributeForm`): replaces the old "Param 1/2/3" boxes. A drop-down chooses what the tile does (all 14 kinds: none, blocked, one-way block, warp, item spawn, NPC avoid, key door, resource node, shop, bank, heal/trap, slide, light source, sound emitter) and the panel shows that kind's own typed fields (whole numbers, decimals, tick boxes, direction and vital pick-lists, hex colour), each with a hint. Id fields show the name of the item, shop or resource they point at (or "no such item"), and anything wrong ("Target X must be at least 0") is listed under the form; building the attribute stays forgiving (bad values fall back to defaults, numbers are clamped) so painting never produces a broken attribute. "Attribute only" paints the attribute without touching tile graphics; "Show on map" toggles the overlay; the NPC spawn picker sits below. The form follows the editor: the eyedropper loading a tile's attribute switches the form to it (`AttributeFormTest` round-trips every kind). The panel scrolls when a form is tall. The Map tab of the Studio now points to it.

**Map properties and map list** (`MapPropertiesPanel`, `MapListPanel`, pure `MapPropertiesForm`; docked right above the Studio): the properties panel edits name, rules (moral), music track, ambient light, the four neighbouring maps (shown by name) and the map size, plus a **Weather and setting** group: an **Interior** tick (interiors ignore weather and day/night), the map's **weather zone** (a pick-list of the game's zones; weather itself is a zone feature authored in `game.json`, not a per-map setting, and in a game with no zones the picker is disabled and each map keeps its fixed legacy weather) and an **Instanced** tick (stored and validated now, copying per party later; an instanced map cannot have neighbours). "Apply changes" writes the typed values to the draft as one undo step (invalid values are listed and block Apply; the world shows light and weather from the draft at once); the fields reload when the draft changes (undo, switching maps). "Resize map" keeps tiles from the top-left corner, adds empty space, drops spawns outside (`MapEditSession.resize`, one undo step). The map list shows every map from the server's catalog (`WorldContentCatalogDto.maps`, a list of `MapSummary` without cells, refreshed after saving or creating a map); clicking one warps there, and with unsaved changes the first click only warns and a second click confirms. "New map" makes a ground-filled map with the next free id. These replace the Studio's hard-coded Town/Outskirts/Crypt buttons and old properties form. Unit-tested (`MapPropertiesFormTest`) and driven through in a browser (apply, warp with the discard warning, new map, resize, validation messages). "Apply changes" and the problem list are pinned below the scrolling form. The Studio's Map tab is now just guidance text, since tools, layers, attributes, maps and properties each have their own panel.

**Shortcuts, dimming and the unsaved-changes prompt** (`EditorShortcuts`, pure and tested): while the editor is open, **B / R / G / E / I / N / V** pick the brush, rectangle, bucket, eraser, eyedropper, NPC-spawn and event tools (they take priority over the game keys E, G and I), **Ctrl+Z** undoes, **Ctrl+Y** or **Ctrl+Shift+Z** redoes, **Ctrl+S** saves the map, **H** shows or hides the grid and **D** dims the layers you are not painting on (`MapEditSession.dimOtherLayers`; the renderer draws every other layer at 30% opacity; there is a toolbar button too). Shortcuts never fire while typing in a text field or with Alt held, and the tooltips show the keys. Closing the editor with **F1** while the map has unsaved changes opens a prompt: *Save and close*, *Discard changes* (`ClientWorldState.discardEditorChanges` puts back the server's version of the map) or *Keep editing* (F1 again also means keep editing). Switching maps from the Maps panel already warned the same way.

**Items, NPCs and Spells panels** (`ContentEditorPanel` over the pure `ContentForm`s `ItemForm`, `NpcForm`, `SpellForm`): each is a master-detail window (floating, hidden until its toolbar button is pressed; dock it like any panel): a searchable list on the left with **New item / NPC / spell**, and on the right a form built from the content form's typed fields, grouped under headings (Basics, Requirements, Weapon and armour, Bonuses when worn, When used...). Whole numbers, tick boxes, pick-lists (types, behaviours, targeting, status), icon / sprite / animation pickers with previews, comma-separated id lists, and a text area for NPC loot (one drop per line: `item min-max chance`, for example `3 1-2 5000`). Id fields show the name of what they point at ("= Iron Sword") or "(no such item)". The per-attribute and per-vital fields (item bonuses, requirements, restores; NPC vitals and attributes; spell costs) come from **the game's own `game.json`** (Hearthvale shows grit/thumb/charm/vigor and hp/sp, Classic shows str/def/int/agi/vit and hp/mp/sp), spells can never cost the life vital, and entries a data file holds for other keys (and explicit zeros) are left exactly as authored. Everything wrong with the typed values is listed under the form (`FormRules`: per-field type, range and choice rules plus each form's own cross-checks against the catalog, such as a drop item that does not exist or an area spell with no radius) and blocks Save. Switching entries with unsaved edits asks first (click again to discard). **Save** sends the definition; the panel shows "Saving..." until the server's catalog arrives with it, and if it never does (the server refused it, with the reason in the chat console) it keeps what was typed and says so. The NPC form also has a **Boss encounter** section (phases, adds, telegraphed attacks and lockout as text lines: `life% attack% speed% adds announcement` and `phase spell SHAPE radius windup cooldown warning`; `NpcForm.parseEncounter`). Items also have a "Give me 1" button. **Roguelike authoring panels (2026-11-21)**: **Game rules** (`GameRulesForm`, `GameRulesPanel`; the whole `game.json` except rarely used sections, which are kept as they are; tables are `|` separated lines; Owner only, `c_admin_save_game`, written to `game.json`, applies after a restart), **Classes** (`ClassForm`, `c_admin_save_class`, live) and **Dungeon** (`DungeonForm`, `DungeonPanel`: the floor recipe `generator`, `scaling` and difficulty tiers of the map being edited, applied to the draft and saved with the map). The spell form also edits *revive* and *ally* casting and the item form *rolls affixes*. **Systems** (`ModulesForm`, `ModulesPanel`, `c_admin_set_modules`: the system tick boxes listed under their genre heading, with a button per genre that ticks that genre's systems and unticks the rest (see [optional modules](/server/optional_modules.md)); Owner only, saved to `server.json` and applied to the running simulation at once; clients see the change in their HUD after their next sign-in), **Action skills** and **Weapon sets** (`ActionSkillForm`, `WeaponSetForm`, `c_admin_save_action_skill`, `c_admin_save_weapon_set`, live; the catalog sent to editors now carries both collections; tables are `|` separated lines). The step-by-step guide is `docs/BUILD_A_ROGUELIKE_IN_F1.md`. What the F1 editors still cannot author is listed in [the authoring gaps issue](/issues/f1_editor_authoring_gaps.md). These replace the old Items, NPCs and Spells tabs of the Studio (about 400 lines of hand-built forms removed). `ShippedContentFormsTest` opens every shipped item, NPC and spell of both games in its form (no complaint, and an unedited save changes nothing) and checks that new entries made by the forms pass the server's content rules in each game.

**Shops and Resources panels** (the same `ContentEditorPanel`, with `ShopForm` and `ResourceForm`): **Shops** edits every shop (the old tab could only edit the first one and flattened every stock entry to "1 of the item"): name, currency item, buy and sell rate percentages, and the stock as a text area with one entry per line, `item amount currency price` (only the item is needed; the price overrides the rate-based one; entries are shown with all four numbers so they round-trip exactly). Problems are listed for unknown items, a duplicate item, a missing currency, and malformed lines. **Resources** edits every gathering node (the old tab could only edit the first): name, kind, tool needed, full and used-up sprites, animation, the item gained, fewest and most per gather, gathers before it is used up, regrow time, XP, and the two messages; it checks that the most is not below the fewest and that the item and animation exist. New shops start with the game's currency item, new resources with an existing item. **Refused saves explain themselves, and the HUD stays clear.** When the server refuses a live save it sends `Save rejected for <collection> #<id>: <reasons>` as a system chat line; `SaveRejection` parses it, `ClientWorldState.lastSaveRejection` keeps the latest, and the content panel shows the reason under the form at once (no more waiting out the 4 s timeout, and no need to find the chat console, which is hidden while the editor is open). The top HUD (the desktop status and button frame, the touch status and Menu button) moves in by the space the docked panels cover (`PlayerHudAndWindows.setViewInsets`), so the F1 toolbar no longer hides it.

**Design review of every panel (2026-11-11)**, judged by whether a non-developer can tell what each is for and find it. Changes made: the game's own windows (status, chat, hotbar, minimap) **step aside while the editor is open** instead of covering the map; the toolbar has a visible **Close editor** button (F1 still works); the status bar shows a **hint for the current tool** ("Click or drag on the map to paint..."); every panel has a one-line description in the **Panels finder**, which also searches it, and the finder lists the keyboard shortcuts and is as tall as the window allows; **Attributes** now docks in the right column (on the left it squeezed Layers until Ground was cut off); **Layers** explains the eye and "above/below"; short content lists start at the top; the **Editor Studio** is a wide floating window with Events, Animations and Admin Tools (the redundant Map tab is gone, and docked in a 440 px column its forms were cut off); and **Admin Tools** warp buttons are built from the game's own maps (they were hard-coded to Classic's "Havenwood" maps, which Hearthvale does not have). Still open, recorded in the [roadmap](/reference/roadmap_status.md): friendlier names for the raw choice values (QUEST_GIVER, HERB_PATCH), a short first-run guide, and redesigning the Events and Animation studios.

**Keeping the screen tidy: minimize, the Editors finder and saved layouts.** The toolbar, status bar and the five map editors are shown at first (the *Map editing* layout, the default since 2026-11-13 owner feedback): **Tileset** and **Layers** docked on the left, **Attributes**, **Maps** and **Map properties** docked on the right (360 px wide); every other editor (the content editors, Admin tools, Art, Help) is one click away. User-facing text says *editor* rather than *panel* (owner feedback, 2026-11-13). Each panel header has **minimize** (puts the panel on a **panel bar**, a strip above the status bar with one button per minimized panel; click its name to bring it back, and the map view makes room for the strip), **collapse** (docked panels shrink to their header), **float or dock**, and **close**. The toolbar has one **Editors** button (or press **P**): a popup with a search box over every panel, grouped (Map, Content, Tools), each showing whether it is open or minimized; type part of a name and press Enter to open the first match. The same popup holds **layouts**: four built-in ones (*Minimal*, *Map editing*, *Content editing*, *Everything*) and the developer's own, saved by name from the current arrangement (which panels are shown or minimized, where, and how big), loaded or deleted later. Saved layouts live in the platform preferences (`morgana-editor-layouts`; up to 20, names of letters, digits and `- _ . ( )`); the current arrangement is still remembered between runs. The saved text starts with a format line (`layout-v3` since the default became *Map editing*): an arrangement saved by an older editor is ignored once, so the new default applies. Rules (`DockLayout.minimize`, `applyPreset`, `serialize`/`restore`, `LayoutLibrary`, `PanelSearch`) are pure and unit-tested; `PanelFinder` and the panel bar only draw them.

**Resizing docked editors** (owner feedback, 2026-11-13): a docked side column is resized by dragging its inner edge, and two stacked docked editors by dragging the line between them (an 8 px invisible strip that shows an accent line and a resize cursor on hover; `EditorWorkspace.Splitter`, kept above docked panels and below floating ones). The rules are pure in `DockLayout`: `setColumnWidth` (between `MIN_COLUMN_WIDTH` 160 px and the 40% side share) and `resizeSplit` (freezes the column's open panels at their current heights, then moves pixels between the two neighbours, neither below `MIN_DOCKED_HEIGHT` 60 px). Dragged sizes are saved with the layout (a twelfth field per panel line, plus `#column|ZONE|width` lines; eleven-field lines from before still restore) and cleared by `reset`/presets. The floating-panel corner grip is now 18 px. Tests: `DockLayoutTest`.

**Whole-pixel editors and a movable finder** (owner feedback 2026-11-13: text in the *Map editing* layout looked distorted, and the Editors finder could not be moved): docked column heights are shared out by weight and drags give fractions, so frames sat on fractional pixels and the pixel font smeared. `EditorWorkspace.placeFrame` now snaps every frame edge (and the Minimized bar) to a whole screen pixel (`snapToPixel`, honouring the UI scale). The Editors finder (`PanelFinder`) is dragged by its title row (kept on screen, remembered while the editor is open). Smoke step: the *Map editing* preset shows the five map editors and the finder moves when dragged.

**Editors stay inside their slots** (2026-11-13): every panel frame clips its content (`PanelFrame` `clip = true`), so content taller than a docked slot is cut at the edge instead of being drawn over the editor next to it (the Layers list, grown by the Clear button, had spilled over the Tileset editor). The Layers list scrolls when its slot is short, and the left column's preferred heights are Tileset 300 / Layers 330.

**Floating panels no longer stack**: opening a floating panel from its toolbar button (`DockLayout.show`) moves it to the first free step of a cascade (80 px, then every 40 px) when its top-left corner would land within 40 px of another visible floating panel, so panels opened one after another fan out; a panel the user dragged somewhere clear keeps its place. A newly opened panel, and any floating panel clicked anywhere, is raised to the front (before this, a panel opened later could appear behind an earlier one).

**Art panel** (`ArtPanel`, pure `ArtGallery` & `ArtImportValidator`): a gallery and live importer for tilesets, icons, characters, worn gear, projectiles and effects with a gold mark on the game's own pictures and a line naming ids the content uses that have no picture; see [make your game's art](/playbooks/make_game_art.md). Enter or click a Target ID and press **Import PNG...** (native file dialog on desktop, `<input type="file">` in the browser) to validate PNG dimensions client-side and upload (`c_admin_import_art`, `EDIT_CONTENT`) for immediate server persistence and live client hot-swap (`s_admin_art_updated`), refreshing thumbnails and the `Tilesets` palette cleanly. Under **Sprites** (`SPRITES`) and **Worn gear** (`PAPERDOLLS`), clicking any item opens a live animated preview across Facing directions and action states (`idle`, `walk`, `attack`, `cast`, `harvest`) — sprites show cell/sheet geometry, while worn gear composites the selected layer over hero sprite #1 using `PaperdollComposer` draw order and any linked item's slot/tint (`ItemDefinition.paperdollSlot`, `paperdollTintHex`, `paperdollHidesSlots`, also editable in `ItemForm`); under **Effects** (`ANIMATIONS`), clicking any strip opens a live looping preview at the matching `AnimationDefinition` frame speed.

**Finishing pass (2026-11-12).** Choice fields show **plain-language names with a one-line explanation** under them (`ChoiceText`: *Quest giver* with "Starts a quest or dialogue when talked to", *Herb patch*, *Aggressive*; the files keep the raw values, and a value with no entry still gets a readable name). A **Help** panel (toolbar Help button, `EditorHelp` text shared with a test that checks every listed shortcut works and every working shortcut is listed) covers what the editor is, the first steps, finding panels, saving and layouts; the status bar says "First time here? Click Help" until it has been opened once (remembered in the editor preferences). **Animations** is its own content panel (`AnimationForm`); the Editor Studio keeps Events and Admin Tools, with a wider list that ellipsizes names, trigger names in words ("Player interacts with it"), clearer labels and top-aligned content. The Panels finder asks twice before deleting a saved layout, and F1 does nothing on the login screen. Tileset reads "Brush: 1 tile from tileset 1". Events became a proper panel on 2026-11-13 (see *Events and animations* above).

**Recipes and Quests panels** (`RecipeForm`, `QuestForm`): **Recipes** edits every crafting recipe (the old tab edited only the first and kept just one ingredient): name, station, level needed, XP, the item and amount made, and the ingredients as `item amount` lines. **Quests** edits every quest (the old tab edited only the first and kept one objective): name, summary, level needed, quests to finish first, repeatable, the objectives as `TYPE target count description` lines (types `KILL_NPC`, `COLLECT_ITEM`, `TALK_TO_NPC`, `HARVEST_RESOURCE`, `CRAFT_RECIPE`, `VISIT_MAP`; the target is an NPC, item, resource, recipe or map id by type), the three texts, and the reward (XP, currency, `item amount` lines, spell taught). Both check that every referenced id exists, matching the server's content rules. The Studio (now the **Admin tools** window) keeps only the admin shortcuts.

**Touch controls and the editor**: the on-screen joystick covers the whole left half of the screen and swallows presses there. It is hidden while the map editor is open (`shouldShowTouchControls`, tested), because on any touch-capable machine (including a desktop with a touch screen) painting on the left half of the map did nothing. Found by asking Scene2D what it hit under the pointer.

**Editor suite direction** (agreed 2026-11-09, in progress; see [roadmap](/reference/roadmap_status.md)): a professional, Mirage Source-inspired map editor with a modern dark look. Panels (toolbar, tileset palette, layers, attributes, map properties, map list, status bar) start **docked** in the classic arrangement and can be torn off to **float**. The map editor comes first, then the Items / NPCs / Spells forms, then the Events and Animation studios. The current single tabbed window remains until each part is replaced.

**Save path**: editor -> `Save*Definition` packet -> server validation (`acceptEdit`) -> live hot swap -> persist -> broadcast ([content pipeline](/content/content_pipeline.md)). A rejected save appears as a system chat message with the JSON pointer of the problem.
Content can still be authored directly as schema-versioned JSON files ([author content as files](/playbooks/author_content_as_files.md)).

## In the browser

The editor works unchanged in the [web client](/architecture/client_web.md); verified in Chrome with a script against a running server. Opening with `F1` (Owner), all tabs render, text fields and drop-downs accept input, and save paths work end to end by updating the server's data files.

Things worth knowing when using or testing it:

* The editable map is only the area inside the map's bounds. Grass beyond an edge is a **neighbouring map** drawn for seamless borders; clicking it does nothing (`applyEditorActionAt` ignores out-of-bounds tiles).
* The content area is a scroll pane (660 x 500). Its buttons, including both Save buttons, are often below the fold, so scroll first. The pane takes the mouse wheel when the pointer is over it (`giveScrollFocusOnHover`); stock Scene2D needs a click first.
* Clicking the world or saving clears only the keyboard focus (`stage.keyboardFocus = null`). `stage.unfocusAll()` also dropped the scroll focus, which made the pane stop scrolling after a map click or a save.
* The window is about 710 px tall, so on a short browser window its lower part is off screen until the window is moved (it is draggable). Some labels are cut off at the right edge ("Deep Water (Anim", "Place/Remove N"); the pane scrolls horizontally.
* When testing from a script, Scene2D text fields do not support triple-click select-all; use Ctrl+A.
